# Archipelago: persistent Hermes FIPS reachability

Status: **onboarding required, not complete**. This describes the host's global
FIPS daemon, not the isolated `fips-lr-a` / `fips-lr-b` LR2021 test daemons.

## Measured facts (2026-11-10)

- LAN identity: `archipelago` at `192.168.50.199`; SSH user `archipelago`.
- Global FIPS binary: `0.4.1 (rev 15db6471db)`.
- The reference Hermes workstation runs FIPS `0.5.1`.
- `systemctl is-enabled fips`: `disabled`.
- `systemctl is-active fips`: `inactive`.
- `/etc/fips/fips.yaml` has `peers: []`.
- Node public identity (`fips.pub`, safe to inventory):

  ```text
  npub1r02tsxt63s4qy698qh3flxsywffh7xwmrdrz22r6hl6pcl8xuw3qrv0tv2
  ```

- Derived FIPS IPv6 address (computed independently with `fipsctl address`):

  ```text
  fd5d:a773:44d1:2c34:1424:caaa:271c:795
  ```

- `archipelago.fips` was not in the fleet hosts maps checked.
- The node's packaged `/etc/fips/hosts` contains public test-mesh aliases, but
  its actual peer list is empty. A packaged alias does **not** make the node a
  member of that mesh.

## Decision

1. **Join the private Hermes FIPS network.** Archipelago is managed fleet
   infrastructure and should use its approved private bootstrap peers and ACLs.
   Do not infer or enable public-network membership from the stock public test
   aliases.
2. **Align the node with the fleet's supported FIPS release** (currently 0.5.1
   on the reference workstation) through the Archipelago OS update mechanism.
   Version skew is worth removing, but it was not the cause of the failed
   `archipelago.fips` lookup: there was no mapping, no peer, and no running
   daemon.
3. **No LR2021 link-protocol or FIPS major-version bump is required for the
   measured host repair.** Batch scheduling, ACK validation and pacing do not
   change the air-frame version. Keep the stable global Hermes daemon separate
   from the experimental `0.6.0-dev` LR2021 test binaries.
4. **Persist through config-as-code, not ad-hoc edits.** The node config says
   `# Generated by archipelago — do not edit by hand.` Use the OS update/config
   path that owns it. Keep `/etc/fips/fips.key` and any nsec material outside
   Git and out of command logs.

## Troubleshooting distinctions

- `unknown host 'archipelago'` → missing npub mapping, not proof of packet loss.
- A resolved `.fips` name with no route → daemon/peer/mesh reachability problem.
- SSH `Permission denied` → authentication/account/authorized_keys problem.
- The LR2021 isolated namespaces working does **not** prove that the global FIPS
  daemon is enabled or that the public/private mesh has a route to the node.

The immediate SSH key issue was already resolved independently: the node's
`authorized_keys` was correct, while the local SSH alias defaulted to the
nonexistent `c08rad0r` account. The local `Host archipelago` entry now selects
`User archipelago` and the correct ED25519 key.
